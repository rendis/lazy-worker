# Lazy Worker working notes

- Write code, comments, and documentation in English. Keep English and Spanish webview strings together in `src/messages.ts`. Localize the native menu in `src-tauri/src/tray.rs`.
- Keep the new-tool checklist in `CONTRIBUTING.md` in step with these notes.
- Introduce the toolbox independently of its current tools in the README. Give each tool the same card under Tools: the poster of its clip, its name, one line, and a link to its user guide section. Put three cards in a row, so the README stays short as tools grow. Show the moving clip at the top of the tool's section in the user guide. List every function of each tool under "What each tool can do" in the README, one line each, so a reader learns what the toolbox does from the README alone. Keep the steps to use them in the user guide.
- Use the [clay workshop](docs/design/clay-workshop/README.md) as the starting point for feature clips. Produce every clip file with its `npm run export -- <tool>` command.
- Hide the macOS panel on close and keep workers running until explicitly stopped or the app quits.
- Acquire the macOS instance lock before app setup. Route repeat launches through the shared panel show path.
- Register launch at login through a per-user LaunchAgent that opens the installed app bundle. Run startup Quick start once after acquiring the instance lock.
- Keep the macOS menu icon legible in the system menu bar appearance and reserve space for its activity badge in both states.
- Hide the existing `NSStatusItem` during a presentation so its activity badge survives restoration.
- Keep the native panel fixed-size in the Tauri window configuration. Keep desktop scrolling inside `<main>` so the sidebar stays fixed.
- Crossfade the theme canvas layers and keep the Settings card geometry stable when its status text is translated.
- Read the full macOS preferred-language list in native code because WebKit may expose only its first entry.
- Read the running version through Tauri's app API. Use the configured bundle version in browser previews.
- Register each module in `src/modules.ts` and mount its shared header so its help, status, timer, and quick-start switch stay consistent with Tools. Keep the timer slot reserved when idle so it can fade without moving the layout.
- Format every time the interface shows through `src/time.ts`. Use `formatSession` for a running or remaining session, `age` for the time since an event, and `formatMoment` for when an event happened.
- A tool can stay on for weeks. Add a new time format in `src/time.ts`, state its longest text there, and reserve that width where it shows. Check it at zero, at one day, and at several weeks.
- Give each module a help popover with one plain paragraph and its `-loop.mp4` clip and poster from `src/assets/clips`. The clay workshop export writes them there, because its renders folder stays out of git.
- Lay out module settings as `.setting-row` lines with an icon, a label, and the control at the end. Use `.segments` for exclusive choices and `.switch` for on/off options. Offer the useful combinations of a tool's options as one named choice, and keep rare options under Advanced, so a user who is not technical decides once. Give each option of a named choice an icon beside its word through `.segment-icons`.
- Mark Quick start with the bolt switch only. Its hint states when the tool starts, based on the startup setting.
- Give a module that sits under a broader sidebar section a `section` in `src/modules.ts`, and a `row` when its card in Tools needs its own name. Show each tool as one card in Tools. A card leads to its module; it opens no rows of its own. Keep the pinned tools in the `pinned` preference, and move the cards only when the user pins or unpins one.
- Send every webview call through the `dispatch` command in `src-tauri/src/dispatch.rs`. Add a `Request` variant and declare `access`, `is_read`, and `runs_on_viewer` for it, none of which has a default arm. Keep a setting that stores a command to run, an address list, or a permission Local-only. Take the origin from the window label, never from request data.
- Run every request a module adds on the device of the window that sent it, and make the module work when its data comes from another device. Show that data as text only.
- Keep the Devices view in `src/devices.ts`. It is not a tool, so it has no entry in `src/modules.ts`. Set every name and text it shows as text, because other devices will send them. Natively show only what is real, and keep the sample list in the browser preview in `src/desktop.ts`.
- Show an open device as a tablist (Access, Permissions, Actions, Log; Tools, Applications, Actions, Connect) built by `tabset` in `src/devices.ts`: one line, each tab a label with its summary as a small badge. One panel shows and every panel has the same fixed height (`--tab-panel-height`: a header line and five rows), so a tab change only crossfades. A panel scrolls inside its `tabBody`, and its empty or error message is centered there. Keys and the last tab are kept per device. Keep alerts above the tabs. Never stack collapsible sections inside a device. Give each way into another device its own row in Connect.
- Post macOS notifications through `src-tauri/src/notifications.rs`, whose `UNUserNotificationCenter` delegate routes a click. Tauri's notification plugin reports no click on desktop. Test from the app bundle opened with `open`: a binary started directly gets no permission.
- Keep the mailbox in `src-tauri/src/remote/mailbox.rs`. The controller delivers directly and polls the controlled device's outbox; the controlled device never connects out. Its file data moves through the transfer queue, the app keeps no copy of what arrived, and outbox copies go on ack or after 7 days.
- Block the web context menu outside text fields and selected text in `src/main.ts`. The panel has no right-click actions.
- Copy text through `CopyText` (the native pasteboard), never `navigator.clipboard` after an await: WKWebView drops the click.
- Change the SSH server only through `remote::access`, with one administrator prompt that runs a fixed script. The script checks `sshd -t` before it keeps our drop-in `000-lazy-worker.conf`, and it never touches other files in `sshd_config.d`. The user name is its only interpolated value. Turn on Remote Login with `launchctl`, never with `systemsetup`, which needs Full Disk Access.
- List first the found devices with an open pairing window in Add device. Keep the other `_ssh._tcp` hosts behind a count that the user opens, as information only rows in a list that scrolls inside its own height, because macOS advertises every Mac with Remote Login on.
- Find devices on the network through the system `dns_sd` API in `src-tauri/src/remote/discovery.rs`. Never open an own mDNS socket. The only service this device advertises is `_lazyworker-pair._tcp`, through `src-tauri/src/remote/advert.rs`, while a pairing window is open: it holds the account and the device id and never the code, and it ends with the window.
- Confine each Files path to its shared root after `canonicalize` in `src-tauri/src/remote/files.rs`. Grant Files only at the device that shares it, for a time, read only or read and write. Send file data in chunks through the transfer queue, never through the webview.
- Open a remote file only by saving it into `<config>/opened/<random>` (mode 0700) through the transfer queue, then `/usr/bin/open <absolute path>`. A rename (`renameEntry`) stays in its folder and never replaces an entry. The explorer asks inline before an upload replaces a file.
- Keep proxy logic in `src/proxy.ts` and reach the system only through `desktop`. Give each `desktop` proxy call a browser-preview result.
- Store a proxy command as a template where `{server}` stands for the server address. Store `null` for an unchanged built-in command. Save a command of the user's own exactly as written, and ask for the server address only when the command names it.
- Ask before an action that cannot be undone, in the place where the user started it.
- When a file grant is saved, read each protected folder inside it from the app process, so macOS asks while the person is at the device. A remote read that macOS refuses (`EPERM`) answers `filesPrivacyDenied`.
- Give a name in a row one line with an ellipsis and a tip with the full name. Give an element inside `.collapse` no width that its content sets, so a long name cannot make the view scroll sideways.
- A remote origin never starts the proxy server or changes where it listens or what it reaches, and its reads hide stored commands. Check the helper path before any managed `authorized_keys` line, and clean every name from the network through `clean_name`.
- Treat proxy clients as apps to open, with no running state. Start selected opens the marked ones. Stop selected leaves them open.
- Reach other devices only through `remote::ssh` with our own `-F` config, a validated `Destination`, and `--` before the host. Never pass user text as ssh options or as the remote command.
- On the target side, run every remote request through the same dispatcher as the webview, with an `Origin::Remote` built from the peers store on each request. The helper only relays bounded lines. Managed `authorized_keys` lines carry `restrict`.
- Run the proxy server on standard threads in `src-tauri/src/proxy/server.rs`. Admit only the local network when the allow list is empty. Refuse targets on the server's own machine.
- Keep the built-in client commands equal in `src/proxy.ts` and `src-tauri/src/proxy/apps.rs`. Launch a client from its saved id, and check the server address before it enters a command.
- Keep the element of a rendered list row and update it in place, so its switch, selector, and disclosure can animate. Rebuild a row only when its name, icon, or language changes. Open a new row and close a removed one over a short time, so the rows under it move instead of jumping.
- Open and close content through `.collapse` with `data-open` and `inert`. Keep `hidden` for content that swaps with other content.
- Give a closed popover no height. A hidden element that keeps its size still adds to the scroll area of its view.
- Style every scroll bar through the shared `::-webkit-scrollbar` rules, thin and in the line color. Keep the space of the main scroll bar reserved, so content does not shift when it appears.
- Keep every image a file under `src/assets`. The content policy allows no `data:` images, so Vite must not inline assets.
- Show the brand mark of a built-in proxy tool from `src/assets/brands`. The marks come from Simple Icons. To offer a new brand in the icon picker, add its file there and its name to `brandNames` in `src/proxy.ts`.
- Save a setting without a notice. Show the progress notice only while the app does work the user can wait for, such as starting, stopping, or changing a running session.
- Discard unsaved input in a module view when the user leaves that view.
- Explain an option whose name is technical with an info icon beside its name. Give the icon `data-tip-text` with a message key, and write the tip in plain words for a user who is not technical.
- Name every icon-only choice with a tip and an accessible label. Tie a tip to hover or keyboard focus, so a mouse click does not leave it open.
- Put `data-tip` on a wrapper when a disabled button must say why it is off. Use an icon button with a tip for a secondary row action.
- Give each built-in proxy tool an `app` and a `code` command. List App first and use it as the default. Find a desktop app by its bundle identifier.
- Turn on a device's full shell only at the target device, never from a remote window and never in pairing. Put `pty` only on the `authorized_keys` line of a peer whose grant is active, and let the helper end the session when the grant ends.
- Screen Sharing is macOS's own. Lazy Worker adds one per-device permission, Screen (`Access::Screen`), off by default and set only at the exposed device: without it a device cannot read the state with `getScreenSharing`. Only the person at the exposed device turns Screen Sharing on. Open a screen with `vnc://` built from the validated `Destination` of a controlled device, from the main window only.
- Keep the proxy request log in memory with a fixed size. Drop the oldest entry first and clear the log when the server stops.
- Close every open `.log-overlay` window through its own close button when the view changes (`closeWindows` in `src/modules.ts`), so its cleanup runs and the new view takes the focus.
- Show a live list, such as the proxy requests, in a `.log-overlay` window over the view, so the layout under it does not move. Keep the overlay row at the overlay's own height, so a long list scrolls inside the window and never makes the panel scroll.
- Show at most three entries of a list inside a row. Put the rest behind a count that opens the full list in that window.
- Filter a field as the user types when its value has a fixed alphabet, and show its error in the row's own note.
- Center the macOS window buttons in the 42 px title bar through `trafficLightPosition`. Its `y` plus the 16 px button height gives the height of the band that centers them.
- Find command-line clients through the login shell `PATH`. Open a command-line client through a `.command` script in Terminal, and run an `open` command directly.
- Derive Tools bulk actions from the runtime state of modules included in Quick start. Keep the action layout stable until a bulk operation finishes. Keep the bulk actions on the Tools title line, so their changing width never moves the tool list. Share one surface across single actions so only their icon and label crossfade. Keep row power available independently of the selection.
- Keep active power buttons visibly recessed in terracotta until their module stops.
- Derive each sidebar running dot from its module's runtime status, independent of the current page.
- Keep system input and power APIs inside the activity adapters. Shared scheduling and preferences must work with the unsupported-platform adapter.
- Change the closed-lid sleep switch only through `src-tauri/src/lid.rs`, and only while Caffeinate is on. Check its permission by the rule file. `sudo -l` also succeeds for a command that still needs a password. Leave a switch the user set before as it is until the user chooses another option. Keep its marker file in step with the switch, so a launch after a forced exit turns it off.
- Open and close a note that depends on a choice through `.collapse`, and keep its last text while it closes.
- List Caffeinate process targets by PID and executable basename. Preserve the current sleep assertion if switching to a process fails.
- Check Accessibility in the same helper that posts Activity events and keep feedback outside the module layout.
- Anchor permission notices to their warning icon and keep them outside the scrolling content.
- Use one pending Accessibility status in Settings for Activity and hiding while sharing. Give each feature its own icon.
- Dismiss permission notices on outside clicks and keep general results in the shared bottom-right notification stack.
- Gate pointer movement on the system idle counter and skip it while any standard mouse button is held.
- Keep both the Tauri bundle and Swift helper deployment targets at macOS 12.0. Keep the frontend build target compatible with Monterey's WebKit.
- Use `npm run build` and `cargo test --manifest-path src-tauri/Cargo.toml` for changes to the shared app. Use the Intel bundle command in the [development guide](docs/development.md#build-for-macos) for changes to macOS integration.
- Verify the packaged helper and Accessibility permission on Monterey before reporting hardware compatibility. Verify presence in the target app separately from process status.
- Keep the pairing key in `src-tauri/src/remote/pairing_key.rs` public on purpose: it reaches only `remote --pair`, and only while a pairing window is open. The 6-digit code that SPAKE2 checks is the secret. The target saves nothing before it checks the controller's confirmation, and the controller saves nothing before it checks the target's.
- Open an application of another device only by a bundle id from that device's scanned list, through `/usr/bin/open` with the absolute path that the scan found. Keep its icons in `<remote>/icons` under hash names, keep only a PNG of at most 256 px and 256 KiB, and let the asset protocol scope in `tauri.conf.json` name that folder alone.
- Keep security events (pairing, removal, shell, key changes, action runs) in their own log file, written only through `Log::append`. Write what a device sent through `Log::append_request`, which coalesces repeated refusals. A schedule belongs to the device that set it, and a device that loses its access or Actions loses its schedules and runs.
- Define an action only on its own device, in `src-tauri/src/actions.rs`. A remote read never includes its command text. Record who set each schedule, and remove a device's schedules when its access goes.

## macOS releases

- For signing, Accessibility after an update, or release automation, follow [issue #1](https://github.com/rendis/lazy-worker/issues/1). Describe test platforms by architecture and macOS version.
- Set `APPLE_SIGNING_IDENTITY` to the Developer ID Application identity for release builds. Verify the app and its Activity helper against that certificate in both architecture bundles.
- Check for a newer release again right before an update installs, so one restart reaches the latest version. Show the changes of every version between the one the user had and the one that runs.
- Run every update check through `check` in `src-tauri/src/updates.rs`, so the time of the last check in Settings stays true. A release needs a few minutes to reach the update address, so keep the automatic checks frequent.
- Add the changes of a release to `src/changelog.ts` before the release, in English and Spanish, for a user who is not technical. Give a change that adds a tool its `tool`. The release command stops without that entry.
- Set the theme in `public/boot.js`, which runs before the first paint, and show the brand mark while the panel loads. The app saves the chosen theme for that script.
- Mark the button the user must press next with `data-attention`, such as Open Accessibility while the permission is missing.
- Keep the panel hidden through `data-booting` on `.workspace` until the app has loaded its preferences and chosen its first view, so no view shows for an instant before another one.
- Hide the title bar bell while the setup guide is open.
- Show the setup guide on a new installation only, which is a launch without saved preferences. Record the version the user has seen in `seenVersion` when the guide or What’s new closes.
- Build each setup guide control on the control of the same setting in Settings: the same `data-` attribute, or `data-mirror` with the id of that control. Give `data-mirror-when="leave"` to a control that changes the system, so it applies when the user leaves its step.
- Record the running tools through `resume::remember` before an update restarts the app, and start them from `resume::take` at launch in place of startup Quick start. Leave proxy clients alone there, because they are still open.
- Require the Tauri updater to verify the signed version. Call `request_restart` after installing so `RunEvent::Exit` releases active tools.
- Local builds default to ad-hoc signing. If Accessibility fails after reinstall, compare the installed app's CDHash with the requirement in the macOS TCC log. Keep the app and Activity helper signing identities stable across releases. Keep private signing keys outside the repository.
- Keep the disk image names free of the version, because the README links to them through the latest release.
- Keep the disk image picture and its window layout in `scripts/disk-image`. Keep `background.png` at the window size and `background@2x.png` at twice that size. Move an icon in `settings.py` when its pad moves in the picture, and record how the picture was made in `background.json`.
- Archive the stapled app for the Tauri updater and bind its signature to the release version before publishing `latest.json`.
- Publish with `npm run release -- <version> --summary "<one line>"`, from a clean `main`. It sets the version, builds and notarizes both architectures, rehearses the update from the last release, and leaves a draft on GitHub. Rehearse a change to the release steps with `npm run release -- --dry-run`.
- Keep the release steps in `scripts/release.mjs`. Keep local names, such as the signing identity, in `.release.local.json`, which git ignores.
- Keep `scripts/release-verifier` on the `tauri` and `tauri-plugin-updater` versions the app ships.
